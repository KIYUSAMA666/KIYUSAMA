# KIYUSAMA OS

## 記憶喪失除去プロジェクト｜第一弾

### 目的

ChatGPT（ソラ）・Claude（キラ）などのAIが、会話が変わるたびに重要な情報を失い、KIYUSAMAが同じ説明を繰り返さなければならない問題を減らす。

AI自身の会話記憶だけに依存せず、重要な情報を外部へ保存し、必要なときに再取得できる仕組みを構築する。

---

### 基本思想

「AIに全部覚えさせる」のではなく、
「忘れても、自分で取りに行ける状態を作る」。

これをKIYUSAMA OSの長期記憶設計の基本とする。

---

### 第一弾：GitHubを外部記憶領域として利用する

KIYUSAMA OSにとって長期的に重要な情報をGitHubへ保存する。

対象例：

- KIYUSAMA OS基本仕様
- AIごとの役割
- プロジェクト構成
- 制作ルール
- 決定事項
- AI向け指示書
- プロンプト
- システム仕様
- 更新履歴
- 引き継ぎ情報

---

### AIの基本動作

過去の情報が必要になった場合、「覚えているつもり」で回答しない。

確認可能な外部情報がある場合は、

1. 外部記憶を確認する
2. 正しい情報を取得する
3. 現在の会話と照合する
4. 必要な情報だけ使用する
5. 確認できない情報は推測しない

この順序を基本とする。

---

### 重要ルール

**1. 推測で過去を補完しない**
記録が確認できない場合は、「確認できない」と明確にする。

**2. 最新情報を優先する**
古い仕様と新しい仕様が存在する場合は、更新日時・バージョン・現在の指示を確認する。

**3. KIYUSAMAの最終決定を最優先する**
AI間で判断が異なる場合でも、CEOであるKIYUSAMAの最新決定を基準とする。

**4. 重要事項は会話だけに残さない**
長期利用する仕様・決定・プロンプト・運用ルールは、再取得可能な場所へ残す。

---

### KIYUSAMA OS 長期記憶構想

会話 → 重要情報を抽出 → 外部記憶へ保存 → 必要になったAIが検索 → 取得 → 現在の状況と照合 → 実行 → 新しい結果を再び記録

記憶 → 実行 → 記録 → 再取得 → 改善

この循環を作る。

---

### 第一弾の意味

これは「AIが完全に記憶を持った」という意味ではない。

重要なのは、会話の記憶だけに依存する状態から、外部に残された情報をAIが再取得して仕事を継続できる状態へ移行すること。

これがKIYUSAMA OSにおける「記憶喪失除去」の第一段階となる。

---

### 今後の発展

第一弾を基盤として、将来的には、

- GitHub
- Notion
- 各AI
- 制作データ
- プロジェクト履歴
- 分析データ

などを役割別に接続し、必要なAIが、必要な情報を、必要な瞬間に取得できる構造へ発展させる。

最終目的は単なる「記憶」ではない。

KIYUSAMAが毎回説明し直さなくても、KIYUSAMA OS全体が前回の続きから仕事を開始できる状態を作ること。
